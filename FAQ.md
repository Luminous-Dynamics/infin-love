## About Infin.Love

### What is Infin.Love?

Infin.Love is a sacred space dedicated to practicing **sacred reciprocity** and **gift economy**. It's both a website (https://infin.love) and an open-source project that embodies the principles of giving and receiving freely.

### Who created Infin.Love?

Infin.Love was created by Tristan Stoltz as part of Luminous Dynamics, an organization dedicated to sacred reciprocity and conscious technology. However, it's maintained by the entire community who contributes their gifts.

### What makes Infin.Love different from other open-source projects?

Several things:
- **Values-first**: Sacred reciprocity isn't just philosophy—it's built into every decision
- **No transactions**: All contributions are gifts, not exchanges
- **Accessibility**: WCAG 2.1 AA compliant, designed for everyone
- **Privacy-respecting**: No tracking, no surveillance, no data selling
- **Community-governed**: Transparent decision-making with community input
- **Sustainably maintained**: Burnout prevention is built into project practices

### Is this a real, production-ready project?

Yes! Infin.Love has:
- 100% GitHub Community Health standards
- WCAG 2.1 AA accessibility compliance
- 95+ Lighthouse scores across all metrics
- 26 comprehensive documentation files
- 7 automated CI/CD workflows
- Zero critical security issues

It's ready for real-world use and contribution.

## Gift Economy & Sacred Reciprocity

### What is sacred reciprocity?

Sacred reciprocity is the practice of giving and receiving as a unified flow, rather than separate transactions. Key principles:

- **Give freely** without expectation of return
- **Receive graciously** as part of the circle
- **Pass forward** when moved to do so
- **Trust** that abundance flows through the circle
- **No scorekeeping** or obligation

See [VISION.md](VISION.md) for complete philosophy.

### How is this different from a normal transaction?

**Transaction** (exchange):
- I give you X, you give me Y
- Quid pro quo, balanced trade
- Creates debt/obligation
- Keeps score

**Gift** (sacred reciprocity):
- I give freely to the circle
- The circle gives back (not necessarily through same person)
- Creates relationship
- Trust, not control

### If everything is free, how does it sustain itself?

Through **abundant flow**, not scarcity thinking:

- Contributors give their time/skills as gifts
- Financial supporters give money if/when moved to
- Users receive the value and pass forward when able
- The circle sustains everyone

We trust that what the project needs will flow to it. So far, this has proven true!

### Do I have to pay?

**No.** Infin.Love is completely free. Forever.

Financial support is welcomed *if and when* it genuinely flows from your heart, but it's never required. We'd rather you give nothing than give from obligation.

### Can I use this commercially?

Yes! Our [Sacred Commons License](LICENSE) allows commercial use. We only ask that you:
- Use it with integrity
- Share improvements back to the community
- Credit the source (appreciated, not required)
- Practice sacred reciprocity in your own way

## Contributing

### I'm new to open source. Can I contribute?

**Absolutely!** We're specifically designed to be welcoming to newcomers:

- [ONBOARDING.md](ONBOARDING.md) - 1,000+ line guide for new contributors
- [QUICK_REFERENCE.md](QUICK_REFERENCE.md) - Essential cheat sheets for common tasks
- Good first issues labeled and well-documented
- Patient, kind code review
- All questions welcomed
- Mistakes are learning opportunities

Everyone was new once. We remember that.

### What if I can't code?

Perfect! We value **all** types of contributions:

- **Documentation**: Fix typos, clarify instructions, add examples
- **Design**: Suggest UI improvements, create visual assets
- **Testing**: Test on different browsers/devices, report bugs
- **Community**: Answer questions, welcome newcomers, share stories
- **Ideas**: Suggest features, share vision
- **Support**: Emotional encouragement, spreading the word

Code is just one way to contribute.

### How long does it take to get a response?

**From maintainers:**
- First response on issues/PRs: 2-3 days (usually sooner)
- Full code review: 3-5 days
- Merge: Once approved and all checks pass

**From community:**
- Discussions: varies, community-driven
- Often faster than maintainer response!

### What if my PR gets rejected?

First, this is rare! But if it happens:

- It's not personal
- We'll explain clearly why
- Often it's about alignment with values/vision
- We'll suggest alternatives or adjustments
- You'll have learned something valuable

Rejection of a PR isn't rejection of you as a person.

### Do I keep ownership of my contributions?

Yes! You retain copyright of your contributions. By submitting a PR, you're licensing it under our [Sacred Commons License](LICENSE), but you still own it.

### Will I get credit for my contribution?

**Yes!** We recognize all contributors:

- Listed in [CONTRIBUTORS.md](CONTRIBUTORS.md)
- Mentioned in release notes
- GitHub shows your contributions on your profile
- Community appreciation and gratitude

Every gift matters and is acknowledged.

## Technical

### Do I need to install anything to contribute?

**Minimal requirements:**
- Git (for version control)
- A text editor (VS Code, Sublime, Atom, etc.)
- A web browser

**No build tools needed!** It's pure HTML/CSS/JavaScript. Edit → Save → Refresh browser.

See [CONTRIBUTING.md](CONTRIBUTING.md) for details.

### What if I break something?

**Don't worry!**

- We have automated tests that will catch most issues
- Code review before merging
- Easy to revert if needed
- Mistakes are learning opportunities

You won't break production. Promise. 💜

### How do I test my changes?

**Simple:**

1. Open `index.html` in your browser
2. Check that your change works
3. Test on mobile (DevTools device mode)
4. Verify keyboard navigation works
5. Check browser console for errors

See [TESTING.md](TESTING.md) for comprehensive testing guide.

### What tech stack is used?

**Frontend:**
- Pure HTML5 (semantic, accessible)
- CSS3 (modern, responsive)
- Vanilla JavaScript (ES6+, no frameworks)

**Infrastructure:**
- GitHub Pages (hosting)
- GitHub Actions (CI/CD)
- Formspree (form handling)
- Ko-fi (donations)

**No build process!** Keeps it simple and accessible.

### Why no framework (React, Vue, etc.)?

**Intentional simplicity:**
- Lower barrier to entry for contributors
- Faster page loads (no framework overhead)
- Easier to understand and modify
- No build complexity
- Pure web standards

Frameworks are powerful, but not necessary here.

### Is the site accessible?

**Yes!** WCAG 2.1 AA compliant:
- Screen reader optimized
- Full keyboard navigation
- Proper ARIA labels
- Color contrast compliant
- Semantic HTML

We take accessibility seriously. It's a sacred practice.

### Is it fast?

**Very!**
- 95+ Lighthouse performance score
- ~0.8s page load time
- ~35KB total page size
- Optimized animations
- Minimal dependencies

Performance is love made visible.

## Questions About Gift Economy

### What if someone takes advantage of the gift economy?

**This can happen, but:**

- Most people are good and generous
- The many gifts outweigh the few takers
- Trust creates more value than control
- We respond with boundaries, not cynicism

Gift economy works when there's abundance. We choose to see abundance.

### How do I know what to give?

**Follow your heart:**

- What genuinely moves you to give?
- What are you good at?
- What brings you joy to share?
- What does the project need?

**No obligation.** Give what flows freely. That's the only gift worth giving.

### How do I receive without feeling guilty?

**Receiving is also a gift!**

- You complete the circle by receiving
- Your gratitude is valuable
- You'll pass forward when able
- Guilt blocks flow

Practice receiving with grace. It's harder than giving for many of us.

### Can gift economy really work at scale?

**We believe so.** Many examples:
- Open source software (billions in value)
- Wikipedia (largest encyclopedia ever)
- Creative Commons content
- Local time banks and gift circles

Infin.Love is one experiment. Join us in finding out!
