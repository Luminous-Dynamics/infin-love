# Contributing to Infin.Love 💜

First, thank you for considering contributing to this sacred space. Every contribution is a gift that enriches the whole.

## Sacred Principles

This project practices **sacred reciprocity**. We welcome contributions not as transactions but as gifts that strengthen our web of connection. Whether you're fixing a typo or adding a major feature, your contribution matters.

## How to Contribute

### 1. **Understand the Intention**

Before contributing, please take time to:
- Read the [README](README.md) to understand the project's purpose
- Browse the live site at [infin.love](https://infin.love)
- Reflect on how your contribution aligns with sacred reciprocity and infinite love

### 2. **Types of Contributions**

We welcome many forms of contribution:

- **Code**: Bug fixes, features, performance improvements
- **Design**: UI/UX enhancements, accessibility improvements
- **Content**: Copy improvements, translations, documentation
- **Ideas**: Feature suggestions, architectural proposals
- **Testing**: Bug reports, accessibility testing, cross-browser testing
- **Community**: Helping others, answering questions, spreading awareness

### 3. **Getting Started**

#### For Small Changes (typos, minor fixes):
1. Fork the repository
2. Make your changes
3. Submit a pull request with a clear description

#### For Larger Changes:
1. Open an issue first to discuss your idea
2. Wait for feedback before investing significant time
3. Fork and create a feature branch
4. Make your changes
5. Test thoroughly
6. Submit a pull request

### 4. **Development Guidelines**

#### Code Quality
- **Accessibility First**: All changes must maintain WCAG 2.1 AA compliance
- **Performance**: Optimize for mobile devices and slow connections
- **Semantic HTML**: Use proper HTML5 semantic elements
- **Progressive Enhancement**: Site must work without JavaScript for core content

#### Code Style
- **Indentation**: 4 spaces (no tabs)
- **Comments**: Write clear, intentional comments
- **Naming**: Use descriptive, meaningful names
- **Simplicity**: Prefer simple, readable code over clever solutions

#### Testing Requirements
Before submitting, please test:
- ✅ Keyboard navigation (Tab, Enter, Escape)
- ✅ Screen reader compatibility (NVDA, JAWS, or VoiceOver)
- ✅ Mobile responsiveness (Chrome DevTools, real devices)
- ✅ Multiple browsers (Chrome, Firefox, Safari, Edge)
- ✅ Form submission to Formspree
- ✅ No JavaScript errors in console
- ✅ Performance (check Lighthouse scores)

### 5. **Pull Request Process**

1. **Title**: Use clear, descriptive titles
   - Good: "Add skip navigation for keyboard users"
   - Bad: "Fix stuff"

2. **Description**: Include:
   - What changed and why
   - Screenshots for visual changes
   - Testing done
   - Any breaking changes

3. **Checklist** (copy into your PR):
   ```markdown
   - [ ] Tested keyboard navigation
   - [ ] Verified mobile responsiveness
   - [ ] Checked accessibility with screen reader
   - [ ] No console errors
   - [ ] Updated documentation if needed
   - [ ] Follows existing code style
   - [ ] Maintains sacred aesthetic and intention
   ```

4. **Review**: Be patient and gracious with feedback
   - Reviews are gifts of attention and care
   - Engage in dialogue, not debate
   - Stay open to suggestions

### 6. **Commit Messages**

Write clear, meaningful commit messages:

**Format**:
```
Brief summary (50 chars or less)

Longer explanation if needed:
- What changed
- Why it changed
- Any side effects or considerations
```

**Examples**:
```
Add mobile hamburger menu for navigation

Improves mobile UX by:
- Adding hamburger toggle button
- Implementing dropdown navigation
- Maintaining accessibility with ARIA
```

### 7. **Sacred Values in Practice**

When contributing, please honor these values:

#### Accessibility
- Everyone deserves access to sacred spaces
- Design for diverse abilities and technologies
- Test with real accessibility tools

#### Performance
- Respect users' time and bandwidth
- Optimize images and assets
- Minimize JavaScript dependencies

#### Privacy & Security
- Protect user data
- Use secure connections
- Minimize tracking and analytics

#### Beauty & Intention
- Maintain the sacred aesthetic
- Every pixel serves love
- Design choices reflect values

### 8. **What We Won't Accept**

To maintain the sacred integrity of this space:

- ❌ Changes that reduce accessibility
- ❌ Heavy frameworks (React, Vue, etc.) - keep it simple
- ❌ Tracking or invasive analytics
- ❌ Advertisements or commercial promotion
- ❌ Changes misaligned with gift economy principles
- ❌ Disrespectful or divisive content

### 9. **Getting Help**

Questions? Need guidance?

- **Open an issue** with the `question` label
- **Email**: tristan.stoltz@gmail.com
- **Review existing issues** for similar questions

We're here to support your contribution journey. No question is too small.

### 10. **Recognition**

All contributors will be:
- Listed in our contributors file (coming soon)
- Acknowledged in release notes
- Celebrated in our sacred reciprocity practices

Your gifts matter and will be honored.
